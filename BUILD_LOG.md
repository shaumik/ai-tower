# Build Log — NEURAL SPIRE (Tower Defense & Strategy)

A running record of how this prototype was built. Every feature in the game was
generated by prompting an AI coding agent (Claude / Claude Code); the human role
was direction, playtesting, and taste. Hand edits were limited to occasional
one-line tuning of balance numbers. The full commit history in this repository
is the machine-verifiable version of this log.

**Stack decision (locked, session 1):** plain HTML5 canvas + vanilla JS, no
engine, no build step, no external assets — sprites are drawn procedurally,
audio is synthesized with WebAudio. This keeps the whole game in readable
source files that an AI agent can hold in context and edit reliably, and makes
the "no network requests" requirement trivial to guarantee.

---

## Session 1 — 2026-07-22 — playable core loop in one day

- Prompted the agent to build a complete portrait tower-defense loop from a
  one-paragraph pitch: an AI-themed defense game ("Neural Siege") where towers
  are firewalls/defense programs and enemies are malware creatures.
- Got a full working game out of the first long prompt run: grid + path maps,
  tower placement, 10-wave levels, cash economy, lives, win/lose overlays,
  procedural canvas art, synth SFX.
- Iterated the same day on playtest feedback, all by prompting:
  - campaign balance pass across levels;
  - touch UX overhaul — explicit DEPLOY confirm button instead of tap-to-place
    (fat-finger misplacements were the #1 frustration);
  - sell/refund so placement mistakes are visibly recoverable;
  - "fun overhaul": active abilities with an energy meter, 1-of-3 protocol
    chips per run, tower branch evolutions, wave events, combat juice
    (shake, combo counter, slow-mo kills).
- **Locked:** confirm-to-place UX; build → combat phase rhythm; chips as the
  per-run variance mechanic.

## Session 2 — 2026-07-23 — economy, wave design, "Mind Games" depth

- Balance direction locked after playtests: *anti-snowball* — repeat clears pay
  fewer cores, flawless play pays extra, so grinding can't replace skill.
- Prompted a rework of wave design into themed formations (rush, swarm, armor
  column, boss escort…) with on-screen intel so the player can read what's
  coming and counter-build. Levels tightened to 10–24 waves.
- "Mind Games" update, all prompted in one session: terrain tiles, damage
  types, status effects, tower-jamming enemies, mid-run deals, path forks,
  corruption tiles, per-type tower caps.
- **Locked:** waves must be readable and counterable, never just bigger
  numbers.

## Session 3 — 2026-07-23/24 — art direction by mock page

- Built a standalone art mock page (`mock.html`) to iterate visual direction
  cheaply: dark machined towers vs glowing threat creatures. Compared variants
  side-by-side, then prompted the agent to port the winning direction into the
  live renderer — all 12 tower families with unique silhouettes, then all 32
  enemy creature types.
- UI passes: evolution preview in the build sheet, placement card that never
  covers the grid.
- **Locked:** towers dark and mechanical, threats bright and organic — enemy
  legibility beats decoration.

## Session 4 — 2026-07-25/29 — first-minute feel and distribution polish

- "Hot first minute": prompted dense, fast wave openers for the first levels so
  a new player is shooting things within seconds.
- First-run onboarding overlay (highlight ring + one-line hints on the real
  controls), keyboard controls for desktop, side dressing for wide screens.
- Also produced web-portal packaging (ad SDK adapter, store art, PWA/offline
  support) — later removed for this competition, see Session 5.

## Session 5 — 2026-08-14 — competition retrofit of the 2D game

- Prompted the agent to rework the 2D canvas game into an MHCP-compliant
  package: stripped every portal/monetization path (ad adapter, rewarded-ad
  bonus and ad-gated revive, SDK lifecycle hooks, service worker, PWA
  manifest), added a portrait lock, wrote a packager that assembles the
  modular sources into one readable unminified `index.html`, and verified the
  build headlessly (full run to victory + a defeat run, zero network requests,
  zero console errors).
- Reviewing the result against the brief, decided the 2D canvas game was the
  wrong vehicle: the competition calls for Three.js, and a straight retrofit
  showed its portal-game DNA. **Locked: pivot to a ground-up Three.js
  prototype** that keeps the AI-defense fiction but builds the design around
  what 3D uniquely enables.

## Session 6 — 2026-08-14 — NEURAL SPIRE: the pivot to 3D

The design question of the session: *what can a 3D tower defense do that a 2D
one cannot?* The answer that stuck — *verticality and gravity*. One prompt run
produced the concept and most of the game; the rest of the session was
playtest-driven tuning.

- **Concept locked:** the map IS a tower. A portrait-native vertical spire
  with a helical climb ramp; enemies spawn at the base and climb toward the
  summit core; turrets mount on sockets spiraling up the outside. One-thumb
  camera: drag to orbit and climb the view.
- **Gravity as a weapon (the signature mechanic):** Repulsor turrets hurl
  climbers off the ramp; they fall ballistically and die on impact, paying a
  salvage bonus that scales with fall height. Higher repulsor = bigger payout,
  but enemies reach it later — a real placement dilemma.
- **The spire blocks its own defenses:** turrets can't shoot through the
  central column, so coverage angles matter — spreading around the helix beats
  stacking one side.
- **Economy locked (invest–harvest–upgrade):** salvage from kills; 10%
  interest on unspent salvage at each wave start (hoard vs. spend tension); a
  power grid — the core supplies 8 power, every turret drains some, and
  generators add +6 but occupy defense sockets; per-turret overclock bursts
  for salvage; 70% sell refund. Three-level upgrades per turret.
- **Threat mix:** crawlers, fast sprinters, armored brutes, knock-immune
  bosses every 5 waves — and fliers that skip the ramp entirely and rise
  straight up, forcing coverage at altitude.
- Session flow, all prompted: scene/spire/camera scaffold → enemies + turrets
  → economy + waves + end states → HUD sheets → playtest, which caught real
  issues the agent then fixed: camera framed too tight (the column filled the
  portrait view), HUD overflow at 390px, damage numbers stacking into
  unreadable piles (now aggregated per enemy), banner clipping.
- **Verified on the packaged zip build** in a 390×844 portrait viewport,
  driving the real game API headlessly:
  - full 15-wave campaign **victory** with an actively-managed defense
    (upgrades + overclocks), core untouched at 10/10 — 308 kills, ¤561 paid
    in interest;
  - the same defense left unmanaged **loses on wave 15** — managing the
    economy is the difference between winning and losing, which is exactly
    the loop we want;
  - an undefended run **loses on wave 2** — the defeat path fires cleanly;
  - a dedicated probe confirmed repulsor knock-offs: climbers go ballistic,
    splat, and pay the gravity bonus;
  - zero external network requests and zero console errors in every run.
- Packaging per the rules: our game code assembled inline into one readable
  `index.html`; Three.js (the only third-party library) ships in `vendor/`
  inside the zip, referenced by relative path.
